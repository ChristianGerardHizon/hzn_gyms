# Folder Structure

This document describes the architecture and folder organization for the Ebe Gym Flutter application.

---

## Overview

The project follows a **feature-based clean architecture** with three distinct layers:

```
lib/
├── main.dart                 # App entry point
└── src/
    ├── core/                 # Shared functionality across features
    └── features/             # Feature modules organized by domain
```

## Layer Details

### Data Layer

The data layer handles all external data operations.

**Simple features (single DTO/repository):**
```
data/
├── [feature]_dto.dart
├── [feature]_dto.mapper.dart
├── [feature]_repository.dart
└── [feature]_repository.g.dart
```

**Complex features (multiple DTOs/repositories):**
```
data/
├── dto/
│   ├── [feature]_dto.dart          # Response DTO (API -> Domain)
│   ├── [feature]_dto.mapper.dart
│   └── create_[feature]_dto.dart   # Request DTO (Domain -> API)
└── repositories/
    ├── [feature]_repository.dart
    └── [feature]_repository.g.dart
```

> **When to use subfolders:** Create `dto/` and `repositories/` subfolders when a feature has 3+ DTOs or 2+ repositories. This improves organization and makes the data layer easier to navigate.

#### DTOs (Data Transfer Objects)

DTOs are used to decouple API data structures from domain entities. They handle serialization/deserialization and data transformation.

**Combined DTO Pattern (Response + Request in one class):**

```dart
@MappableClass()
class MemberDto with MemberDtoMappable {
  final String id;
  final String name;
  final String? mobileNumber;
  final String? dateOfBirth;
  final String? address;
  final String? sex;
  // ...

  factory MemberDto.fromRecord(RecordModel record) { ... }

  Member toEntity({String? baseUrl}) {
    return Member(
      id: id,
      name: name,
      mobileNumber: mobileNumber,
      dateOfBirth: parseToLocal(dateOfBirth),
      // ...
    );
  }

  static Map<String, dynamic> toCreateJson(Member member) {
    return {
      'name': member.name,
      'mobileNumber': member.mobileNumber,
      'dateOfBirth': member.dateOfBirth?.toUtcIso8601(),
      // ...
    };
  }
}
```

**Key DTO Concepts:**
- `fromRecord(RecordModel)` - Factory to create DTO from PocketBase record
- `toEntity()` - Instance method to convert DTO to domain entity
- `toCreateJson(Entity)` - **Static method** to convert entity to API payload (avoids conflict with dart_mappable's generated `toJson()`)
- Handle type conversions (String dates -> DateTime, num -> formatted String)
- Isolate API field names from domain layer
- Use `@MappableClass()` for serialization support

#### Repository Pattern

Repositories follow the **abstract interface + implementation** pattern with FutureEither for type-safe error handling.

```dart
/// Repository interface for members.
abstract class MemberRepository {
  FutureEither<List<Member>> fetchAll({String? filter, String? sort});
  FutureEither<Member> fetchOne(String id);
  FutureEither<Member> create(Member member);
  FutureEither<Member> update(Member member);
  FutureEither<void> delete(String id);
}

@Riverpod(keepAlive: true)
MemberRepository memberRepository(Ref ref) {
  return MemberRepositoryImpl(ref.watch(pocketbaseProvider));
}

class MemberRepositoryImpl implements MemberRepository {
  RecordService get _collection =>
      _pb.collection(PocketBaseCollections.members);

  @override
  FutureEither<List<Member>> fetchAll({String? filter, String? sort}) async {
    return TaskEither.tryCatch(() async {
      final records = await _collection.getFullList(
        filter: filter ?? PBFilter().notDeleted().build(),
        sort: sort ?? '-created',
      );
      return records.map((r) => MemberDto.fromRecord(r).toEntity()).toList();
    }, Failure.handle).run();
  }
  // ... create, update, delete, fetchOne follow same pattern
}
```

**Key Repository Concepts:**
- **Abstract interface** defines the contract (easy to mock for testing)
- **Implementation class** contains PocketBase-specific logic
- Returns `FutureEither<T>` (typedef for `Future<Either<Failure, T>>`)
- Uses `TaskEither.tryCatch()` from fpdart for clean async error handling
- `Failure.handle` - Standard error handler that wraps exceptions
- Provider returns the interface type, not implementation
- `@Riverpod(keepAlive: true)` keeps repository alive across navigation

#### Application Layer (Services)

The application layer contains business logic, use cases, and orchestration between repositories. Services coordinate complex operations that involve multiple entities or require business rules.

**Service Pattern:**

```dart
@riverpod
class MembershipPurchaseService extends _$MembershipPurchaseService {
  @override
  MembershipPurchaseService build() => this;

  /// Purchases a membership for a member with optional add-ons.
  Future<Either<Failure, MemberMembership>> purchaseMembership({
    required String memberId,
    required String membershipId,
    List<String> addOnIds = const [],
  }) async {
    final membershipRepo = ref.read(memberMembershipRepositoryProvider);
    final salesRepo = ref.read(salesRepositoryProvider);
    // Orchestrate membership creation + sale record
    // ...
  }
}
```

**Key Application Layer Concepts:**
- Contains business logic that spans multiple repositories
- Orchestrates complex operations (create with related entities)
- Implements use cases (transfer, archive, merge)
- Calculates derived data and statistics
- Keeps controllers thin and focused on UI state
- Uses `@riverpod` for dependency injection

**When to Use Application Layer:**
| Use Application Layer | Use Repository Directly |
|-----------------------|-------------------------|
| Multi-entity operations | Simple CRUD |
| Business rule validation | Single entity fetch |
| Complex calculations | List/filter queries |
| Workflow orchestration | Basic create/update |

#### Controllers

Controllers manage UI state and delegate to repositories. Two main patterns are used:

**Standard Controller (keepAlive):**

```dart
/// Controller for managing the members list.
@Riverpod(keepAlive: true)
class MembersController extends _$MembersController {
  MemberRepository get _repository => ref.read(memberRepositoryProvider);

  @override
  Future<List<Member>> build() async {
    final result = await _repository.fetchAll();
    return result.fold(
      (failure) => throw failure,
      (members) => members,
    );
  }

  Future<void> refresh() async {
    state = const AsyncLoading();
    final result = await _repository.fetchAll();
    state = result.fold(
      (failure) => AsyncError(failure, StackTrace.current),
      (members) => AsyncData(members),
    );
  }
}
```

**Family Controller (parameterized state):**

```dart
/// Provider for a single member by ID.
@riverpod
Future<Member?> member(Ref ref, String id) async {
  final repository = ref.read(memberRepositoryProvider);
  final result = await repository.fetchOne(id);
  return result.fold((failure) => null, (member) => member);
}
```

**Key Controller Concepts:**
- `@Riverpod(keepAlive: true)` - State persists across navigation (use for main lists)
- `@riverpod` (lowercase) - State is disposed when no longer watched (use for detail views)
- **Family providers** - Use `build(String id)` parameter for scoped state
- `result.fold()` - Handle Either<Failure, T> from repository
- **Optimistic updates** - Update local state immediately after successful mutation
- Return `bool` from mutations to indicate success/failure to UI

#### Pages

**List Page Pattern with AsyncValue.when:**

```dart
class MembersListPage extends ConsumerWidget {
  const MembersListPage({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final membersAsync = ref.watch(membersControllerProvider);

    return Scaffold(
      appBar: AppBar(title: const Text('Members')),
      body: membersAsync.when(
        loading: () => const Center(child: CircularProgressIndicator()),
        error: (error, stack) => ErrorState(
          message: error.toString(),
          onRetry: () => ref.read(membersControllerProvider.notifier).refresh(),
        ),
        data: (members) => RefreshIndicator(
          onRefresh: () => ref.read(membersControllerProvider.notifier).refresh(),
          child: ListView.builder(
            itemCount: members.length,
            itemBuilder: (context, index) => ListTile(
              title: Text(members[index].name),
              subtitle: Text(members[index].mobileNumber ?? ''),
              onTap: () => MemberDetailRoute(id: members[index].id).go(context),
            ),
          ),
        ),
      ),
    );
  }
}
```

**Detail Page with Family Provider:**

```dart
class MemberDetailPage extends HookConsumerWidget {
  const MemberDetailPage({super.key, required this.memberId});

  final String memberId;

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final memberAsync = ref.watch(memberProvider(memberId));

    return memberAsync.when(
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (error, stack) => ErrorState(message: error.toString()),
      data: (member) {
        if (member == null) return const EmptyState(title: 'Member not found');
        return _buildContent(context, member);
      },
    );
  }
}
```

|--------|---------|
| Architecture | Feature-based Clean Architecture (4 layers) |

| Backend | PocketBase (BaaS) |
| Serialization | dart_mappable (`@MappableClass`) |

### Key Patterns Quick Reference

| Layer | Component | Pattern |
|-------|-----------|---------|
| Data | DTO | `fromRecord()` + `toEntity()` + `toCreateJson()` (static) |
| Data | Repository | Abstract interface + `FutureEither<T>` return types |
| Presentation | Controller | `AsyncNotifier` with `build()` + mutation methods returning `bool` |
| Presentation | Page/Widget | `AsyncValue.when()` for loading/error/data states |
| Presentation | Family Provider | `build(String id)` parameter for scoped state |
